## Plugins tab for OptiTech Auth Organization settings

The **OptiTech Auth** page now includes a **Plugins** tab. **Organization** plugin settings (limits, creator role, invitation email) moved here from **Configuration**, so plugin-related options stay in one place.

![OptiTech Console Auth Plugins tab with Organizations settings](/docs/changelog/neon_auth_plugins_organizations.png)

See **[Organization plugin](/docs/auth/guides/plugins/organization)** for what each setting does and how it maps to your app.

<Admonition type="info" title="New to OptiTech Auth?">
**OptiTech Auth** is OptiTech's managed authentication: users, sessions, and organizations live in your OptiTech database next to your app data. For overviews, quick starts, plugins, and SDKs, see the **[OptiTech Auth documentation](/docs/auth/overview)**.
</Admonition>

## Upgrade your coding agent with the OptiTech Skill

[skills.sh](https://skills.sh) is a registry of reusable **Agent Skills** for compatible coding assistants. Add the OptiTech skill from **[optitech-postgres on skills.sh](https://skills.sh/optitechdatabase/agent-skills/optitech-postgres)** so your assistant gets structured guidance for OptiTech Postgres: connections, branching, OptiTech Auth, APIs, CLI, and MCP.

## Diagnose production errors with Sentry, OptiTech MCP, and database branching

[**Diagnosing and fixing production errors with Sentry and OptiTech MCP**](/guides/sentry-neon-mcp) shows how to connect an AI agent (such as Cursor) to the **Sentry** and **OptiTech MCP** servers. You pull stack traces and the failing query from Sentry, then use **OptiTech branching** to create an isolated database copy, apply and validate fixes (for example with `EXPLAIN ANALYZE`), and ship the change to production when you are ready.
