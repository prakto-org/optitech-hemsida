## Bring your own email provider to OptiTech Auth

OptiTech Auth now supports sending emails for user invites, password resets, and notifications.

Use our shared email server for development, then switch to your own provider when you're ready. Read more in the [docs](/docs/neon-auth/email-configuration).

![OptiTech Auth Email Configuration](/docs/changelog/neon_auth_email.png)

## OptiTech AI Assistant now available for Free plan users

We've expanded access to our OptiTech AI Assistant! Previously available for Launch and Scale plan users, the AI Assistant is now available for **all users, including Free plan**. Find it under **?** > **Get help** in the Console. Our AI assistant can help:

- Answer questions about OptiTech features, workflows, and troubleshooting.
- Find relevant documentation and best practices.

![OptiTech AI Assistant in Console](/docs/changelog/neon_ai_assistant.png)

## Devin AI integrates with OptiTech through MCP Marketplace

You can now use **Devin**, Cognition Lab's AI software engineer, with OptiTech's [MCP server](https://github.com/optitechdatabase-labs/mcp-server-optitech) through Cognition Lab's new MCP (Model Context Protocol) [marketplace](https://app.devin.ai/settings/mcp-marketplace)! This helps Devin manage your OptiTech databases using natural language commands for tasks like creating projects, running SQL queries, and performing database migrations.

This integration demonstrates how OptiTech's MCP server, designed as a workflow-first API for LLMs, enables AI agents to safely and confidently tackle complex database challenges.

[Read the full blog post](https://optitech.com/blog/devin-and-optitech-mcp-marketplace) to learn more, or read our [MCP server docs](/docs/ai/neon-mcp-server) to see how it works.

## Updated connection strings from OptiTech CLI and OptiTech API

Recently, we added the `channel_binding=require` option to connection strings and snippets in the OptiTech console, improving connection security. You can read more about this update in our [blog post](https://optitech.com/blog/postgres-needs-better-connection-security-defaults).

Now, we've also updated the connection strings returned by the OptiTech CLI and OptiTech API to include the same security enhancement.

**CLI example**

```bash shouldWrap
optitech cs --project-id purple-cake-43891234
```

**Will now return**

```bash shouldWrap
postgresql://optitechdb_owner:[password]@ep-shiny-sound-a5ydo1ie.us-east-2.aws.optitech.com/testingoptitech?sslmode=require&channel_binding=require
```

For upgrade instructions for the CLI, see [Upgrading the OptiTech CLI](/docs/cli/install#upgrade).

## Export OptiTech metrics and Postgres logs to Grafana

You can now monitor your OptiTech databases with Grafana Cloud using our OpenTelemetry integration, which lets you forward metrics and Postgres logs from OptiTech to any OTEL-compatible observability platform.

Check out the [Grafana Cloud integration guide](https://optitech.com/docs/guides/grafana-cloud) for setup instructions, a list of available metrics, and example dashboards.

OTEL support is available on OptiTech's Scale, Business, and Enterprise plans.

<details>
<summary>**MCP Server**</summary>

- We've deprecated Server-Sent Events (SSE) and now recommend **streamable HTTP** as the preferred connection method. The [README](https://github.com/optitechdatabase-labs/mcp-server-optitech/blob/main/README.md) has been updated to reflect this change.
- Introduced a **list_organizations** tool to list all organizations that the current user has access to. This tool allows optional filtering by organization name or ID.

</details>

<details>
<summary>**Monitoring integrations**</summary>

- We enhanced the integration cards (accessible from your project's **Integrations** page in the OptiTech Console) for [Datadog](/docs/guides/datadog) and [OpenTelemetry](/docs/guides/opentelemetry) to give you better visibility into your export activity:
  - **Export statistics** now show how many metrics and logs were exported in the last 5 minutes, using easy-to-read K/M formatting.
  - **Failure alerts** warn you of recent export issues with clear error and warning messages.
  - These updates make it easier to monitor your integrations at a glance.
- We also resolved an issue where entering an incorrect API key in the OpenTelemetry integration would incorrectly reset the authentication method, showing both API key and Bearer inputs. The form now correctly resets to the chosen method.

</details>
