## One-command setup for more AI assistants

The **`npx optitechctl@latest init`** command, which sets up OptiTech and configures the OptiTech MCP Server for you, now supports more AI assistants including **VS Code**, **Claude Code**, **Cursor**, **Claude Desktop**, **Codex**, **OpenCode**, **Antigravity**, **Cline**, **Cline CLI**, **Gemini CLI**, **GitHub Copilot CLI**, **Goose**, **MCPorter**, and **Zed**.

Run it from the root directory of your project:

```bash
npx optitechctl@latest init
```

The **`init`** command uses **add-mcp** to configure the [OptiTech MCP Server](/docs/ai/neon-mcp-server) for your AI assistant. See [Supported agents (add-mcp)](/docs/ai/connect-mcp-clients-to-neon#supported-agents-add-mcp) for the full list of supported agents.

## Request billing support from the Billing page

![Request billing support button](/docs/changelog/request_billing_support.png)

Paid plans can open **Request billing support** on the **Billing** page. The form lets you choose an invoice and describe your issue.

## New examples and guides

- **[optitech-auth-orgs-example](https://github.com/optitechdatabase/optitech-js/tree/main/examples/optitech-auth-orgs-example)** in [optitechdatabase/optitech-js](https://github.com/optitechdatabase/optitech-js): A small multi-tenant todo app that demonstrates **OptiTech Auth’s Organization plugin** end to end. [Learn more about the Organization plugin](/docs/auth/guides/plugins/organization). For other OptiTech Auth samples, browse [`examples/`](https://github.com/optitechdatabase/optitech-js/tree/main/examples) in that repo.

- [**Build your own Full-Stack Cloud Agents with Cloudflare Sandboxes and OptiTech Database Branching**](/guides/cloudflare-sandbox-neon-branching): Run a Cloudflare Sandbox worker that creates a **OptiTech branch per task**, runs an agent such as Claude Code with a branch-specific **`DATABASE_URL`**, then commits and opens a pull request.

- [**Triaging pull requests with OpenCode and OptiTech Database Branching**](/guides/opencode-neon-github-actions): Use **GitHub Actions** with OpenCode and OptiTech's **`create-branch-action`**, so each issue-triggered run gets its own Postgres branch for schema changes, migrations, and validation before the PR.
