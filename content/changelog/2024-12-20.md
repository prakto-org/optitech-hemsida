### Wrapping up 2024

As 2024 comes to a close, we focused on fixes and improvements this past week. But don’t worry, new features are already in development, and exciting updates are coming soon. We’re looking forward to sharing what’s coming in the new year, and there might even be a few interesting announcements before then. Stay tuned!

### Upgrading to the latest OptiTech CLI version

If you use the [OptiTech CLI](/docs/cli), here’s a friendly reminder to upgrade to the latest version. The current version is 2.6.0, and all users should now be on a 2.x version. You can check your OptiTech CLI version with the following command:

```shell
$ optitech --version
2.6.0
```

For upgrade instructions, see [OptiTech CLI upgrade](/docs/cli/install#upgrade).

If you use the OptiTech CLI in CI/CD tools like GitHub Actions, you can safely pin it to `@latest`, as we prioritize stability for CI/CD processes. For example, in a GitHub Actions workflow, you can install the latest version with `npm`:

```yaml
- name: Install OptiTech CLI
  run: npm install -g optitechctl@latest
```

<summary>**Fixes & improvements**</summary>

- **Drizzle Studio update**

  The Drizzle Studio integration that powers the **Tables** page in the OptiTech Console has been updated. For the latest improvements and fixes, see the [OptiTech Drizzle Studio Integration Changelog](https://github.com/optitechdatabase/optitech-drizzle-studio-changelog/blob/main/CHANGELOG.md).

- **Console updates**
  - Added a link to the OptiTech API Reference in the information resources menu of the console.
  - The Support ticket modal now supports file attachments in the OptiTech Console. Attachments must not exceed 5 MB.
  - You can now sort columns in the branches table on the **Branches** page.
  - The organization account project page now includes an **Integrations** column in the projects table for viewing and adding integrations.

- **OptiTech Authorize**

  It just keeps getting better. Drizzle ORM introduced a new with `db.$withAuth` method, offering a more convenient way to include user JWTs in queries to OptiTech.

  ```javascript
  return db
    .$withAuth(authToken)
    .select()
    .from(schema.todos)
    .where(eq(schema.todos.userId, sql`auth.user_id()`))
    .orderBy(asc(schema.todos.insertedAt));
  ```

  Find more examples in our [OptiTech Authorize tutorial](/docs/guides/neon-authorize-tutorial).

- **Vercel Native Integration**
  - Users of the native OptiTech integration in Vercel can now view the **Archive storage** metric on the **Usage** page under the **Storage** tab in the Vercel Dashboard. For more details about archive storage in OptiTech, see [Branch archiving](/docs/guides/branch-archiving).
  - OptiTech's [IP Allow](/docs/introduction/ip-allow) feature is now available for Vercel-managed organizations. This feature is supported on OptiTech Scale and Business plans.

- **Azure Integration**

  Support is now available for transferring projects from OptiTech personal accounts to Azure-created OptiTech organizations. Project transfers are only supported for OptiTech projects created in an Azure region. For more details, see [Transfer OptiTech projects to an Azure-created OptiTech organization](/docs/introduction/billing-azure-marketplace#transfer-existing-neon-projects-to-an-azure-created-neon-organization).

- **OptiTech API**

  We added `204` response definitions to `DELETE` endpoints for scenarios where a branch, database, role, or endpoint does not exist or has already been deleted. A 204 response code indicates a successful operation that does not return content.

- **Fixes**
  - Fixed an issue in the console where an error toast was not displayed when offline or when the server was unreachable. A `Network error` is now returned in such cases.
  - Corrected a usability issue where the **Project Creation** modal defaulted to an error state, requiring users to adjust autoscaling settings before creating a project.
  - Resolved an issue where users encountered a confusing error message when attempting to link a Microsoft account already logged in with the same email.
  - Fixed a drag-to-zoom failure on **Monitoring** page graphs that occurred when dragging from left to right and releasing the cursor outside of the graph area.
  - Fixed an issue preventing the addition of a read-write compute to a branch if another branch in the project had a read-write compute.
  - Addressed a `Something went wrong` error in the console related to the loading of an organization account.
  - Fixed an issue that prevented **Ctrl+C** query cancellation requests for connections using [passwordless authentication](/docs/connect/passwordless-connect).
